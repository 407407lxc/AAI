# AAI Development Handoff Guide

This document is written for future agents and developers that need to continue the Agentic AI Infrastructure (AAI) work in this repository.

The goal is to make the next agent productive without relying on prior chat context.

## 1. Project identity

**Repository:** `407407lxc/AAI`

**Active branch:** `aai-harness-workflow`

**Main PR:** `https://github.com/407407lxc/AAI/pull/1`

**Current focus:** Build an AAI harness layer that follows the useful control-plane structure of the original full-agent / LoongFlow project, but replaces the workflow semantics and implementation with the user-designed AAI workflow.

AAI is not meant to be a simple prompt wrapper around Codex. AAI owns the workflow, records structured decisions, constrains executor backends, evaluates evidence, archives outcomes, updates memory, and selects future parents.

## 2. Why this project exists

The original project contained two broad styles of work:

1. **Agent-assisted retained kernels**: human-guided and agent-assisted kernel optimization artifacts.
2. **Full-agent / LoongFlow traces**: an autonomous workflow package with planner, executor, evaluator, summarizer, checkpoint database, and population search history.

The current AAI branch intentionally removed old retained-kernel directories, old skills, historical reports, and full-agent traces because those artifacts are not required as vendored runtime dependencies.

However, the **architectural idea** from full-agent / LoongFlow remains important:

```text
Planner -> Executor -> Evaluator -> Summarizer -> Checkpoint / Parent Selection
```

AAI should preserve that kind of structured workflow control, while replacing the old workflow with the user-designed AAI flow.

## 3. Development target

The target system is:

```text
AAI hard workflow engine
  -> structured planner decision
  -> bounded executor backend, such as Codex
  -> evaluator / gate / archive
  -> campaign summary
  -> long-term memory + TRAPS
  -> population checkpoint / next-parent selection
```

Key principle:

```text
AAI owns the workflow.
Agent backends execute bounded nodes.
```

Codex, Claude Code, LoongFlow-compatible runners, or manual edits should be treated as interchangeable backends for specific workflow nodes. They must not own the global campaign state.

## 4. Non-goals

AAI is not trying to:

- vendor the old `full-agent/` trace package;
- keep historical retained kernels in the repo;
- make Codex decide the entire workflow through natural-language prompt instructions;
- store API keys or tokens in repository files;
- let child agents edit evaluator, scoring, archive, or memory files unless a Mode 3 harness proposal is accepted;
- replace evaluator scripts before there is evidence that replacement is needed.

## 6. Current module map

### `schemas.py`

Defines timestamped JSON-compatible data structures:

- task specs;
- metrics;
- artifact refs;
- evidence records;
- gate results;
- proposal reviews;
- timestamp version helper.

Use these structures whenever a new persistent artifact is added.

### `paths.py`

Centralizes path conventions for:

- repository root;
- `agent-assisted/` project root;
- `.aai/` root;
- archive directories;
- campaign directories;
- solution/config resolution.

Do not scatter ad-hoc `.aai` paths in new code. Add helpers here if needed.

### `bootstrap.py`

Implements Mode 0 baseline bootstrap:

- resolves a target task from `config.toml`;
- packs the current solution with `scripts/pack_solution.py`;
- snapshots config and solution source;
- optionally runs local baseline evaluation;
- writes baseline evidence under `.aai/archive/<definition>/baseline/<version>/`.

### `workflow.py`

Implements the hard AAI workflow state machine.

Authoritative campaign control artifact:

```text
.aai/campaigns/<campaign_id>/workflow.json
```

Current states:

```text
TASK_RESOLVED
BASELINE_READY
ROUND_PLANNED
CHILD_PREPARED
AGENT_RAN
EVALUATED
GATED_ARCHIVED
SUMMARIZED
MEMORY_UPDATED
PARENT_SELECTED
PROPOSAL_REVIEW
```

Current actions:

```text
bootstrap_baseline
plan_round
prepare_child
run_agent
evaluate_child
gate_archive
summarize_campaign
update_memory
select_parent
review_proposal
```

Future agents should extend this module when adding new hard workflow stages. Do not rely on prompt text to enforce global flow constraints.

### `planner.py`

Implements a structured, LoongFlow-style planner artifact.

Output:

```text
.aai/campaigns/<campaign_id>/plans/plan-<version>.json
.aai/campaigns/<campaign_id>/plans/plan-<version>.md
```

The plan includes:

- parent id;
- child ids;
- objective;
- constraints;
- agent backend;
- evaluator mode;
- memory inputs;
- traps to avoid;
- next action.

The current planner is a rule planner. Future work can add LLM, Codex, Claude Code, or LoongFlow-compatible planners as backends, but planner output should remain structured JSON.

### `workspace.py`

Creates and manages isolated child workspaces:

```text
.aai/campaigns/<campaign_id>/children/<child_id>/
  child.json
  parent_solution/
  workspace/
    config.toml
    solution/
  ITERATIONS.md
  trajectory.json
  audit.json
  diff.patch
  result.json
```

Child executors should edit only:

```text
workspace/solution/
```

### `codex_adapter.py`

Implements Codex CLI as the first executor backend.

Persistent config:

```text
.aai/codex_config.json
```

It stores:

- model name;
- Codex binary;
- sandbox mode;
- timeout;
- API-key environment variable name;
- optional command template.

It must not store API key values.

### `runtime_logging.py`

Writes detailed runtime diagnostics for Codex and evaluator commands:

```text
runtime_trace.jsonl
environment.json
commands/*.stdout.log
commands/*.stderr.log
```

Environment snapshots redact variables whose names look like keys, tokens, secrets, passwords, auth values, or credentials.

### `child_eval.py`

Runs existing evaluator scripts against isolated child workspaces.

Modes:

```text
pack       -> scripts/pack_solution.py only
local      -> pack + scripts/run_local.py when FIB_DATASET_PATH is available
modal-full -> pack + scripts/run_modal_multiple_gpus.py
```

Outputs:

```text
child_eval.json
solution.json
benchmark_detailed_results.json
retained_run.log
result.json
diff.patch
runtime/eval-<version>/...
```

### `gates.py`

Promotion gate logic.

Checks include:

- evidence schema compatibility;
- failed or incomplete benchmark statuses;
- protected path edits;
- suspicious diff patterns;
- edits outside default `solution/` scope.

Gates should block promotion when evidence is incomplete or suspicious. Warnings can be used for non-blocking risks.

### `archive.py`

Archives baseline, variant, and failed evidence.

Archive layout:

```text
.aai/archive/<definition>/
  baseline/<version>/
  variants/variant-<version>/
  failed/failed-<version>/
  harness-ledger.md
  traps/TRAPS.md
```

Gate failures should not disappear; they should become failed evidence where possible.

### `round.py`

High-level single-child round orchestration.

Current command:

```bash
python -m aai_harness.cli run-child-round ...
```

It prepares/evaluates/gates/archives and writes `round_report.json`. It is useful, but it is not yet the final hard-workflow runner. The next step should be a workflow-aware `run-agent-round` or `workflow-run` that advances through `workflow.py` states automatically.

### `summary.py`

Reads child round reports and writes campaign-level rollups:

```text
campaign_summary.json
campaign_summary.md
```

Summaries include:

- child counts;
- gate pass counts;
- archived variants/failures;
- status counts;
- mode counts;
- repeated gate failure codes;
- best child by metric;
- recommended next steps.

### `memory.py`

Appends campaign findings into long-term memory:

```text
archive/<definition>/harness-ledger.md
archive/<definition>/traps/TRAPS.md
```

Also writes:

```text
.aai/campaigns/<campaign_id>/memory_update.json
```

### `population.py`

Adds LoongFlow-style population/checkpoint lineage memory.

Outputs:

```text
.aai/archive/<definition>/population/population.json
.aai/archive/<definition>/population/checkpoints/checkpoint-<version>/
```

All archived variants and failures can be admitted as lineage evidence. Only gated variants are eligible as best members.

### `parent_selection.py`

Currently implements simple metric-based parent selection. This should eventually be upgraded to use `population.py`, novelty, traps, failure history, and objective fit.

### `campaign.py`

Older campaign-state utilities:

- initializes campaign directories;
- writes narrow round prompts.

This remains useful but should gradually be integrated under `workflow.py` + `planner.py`.

### `proposal.py`

Mode 3 harness proposal workflow.

Use this when repeated evidence suggests the harness itself needs changes. Child agents should not directly edit harness/evaluator/scoring code without proposal review.

### `cli.py`

CLI entrypoint. Current command groups include:

- bootstrap and init;
- Codex config/status/run;
- workflow init/status/advance;
- structured planning;
- child workspace/eval/round;
- gates/archive;
- summary/memory;
- population admission/status;
- proposal review.

## 8. Recommended current workflow

This is the intended manual workflow as of this guide.

### 8.1 Configure executor backend

```bash
cd agent-assisted
export CODEX_API_KEY=<your OpenAI API key>

python -m aai_harness.cli configure-codex \
  --model <codex-model-name> \
  --api-key-env CODEX_API_KEY
```

### 8.2 Start AAI

```bash
python -m aai_harness.cli start \
  --config-path <definition>/config.toml \
  --campaign-id campaign-demo \
  --codex-model <codex-model-name>
```

This creates:

```text
.aai/campaigns/campaign-demo/aai_start.json
.aai/campaigns/campaign-demo/workflow.json
```

### 8.3 Inspect workflow

```bash
python -m aai_harness.cli workflow-status \
  --campaign-id campaign-demo
```

Expected initial state:

```text
TASK_RESOLVED
```

Allowed next action:

```text
bootstrap_baseline
```

### 8.4 Bootstrap baseline

```bash
python -m aai_harness.cli bootstrap \
  --config-path <definition>/config.toml \
  --version <timestamp-version>

python -m aai_harness.cli workflow-advance \
  --campaign-id campaign-demo \
  --action bootstrap_baseline \
  --artifact baseline_manifest=.aai/archive/<definition>/baseline/<timestamp-version>/manifest.json
```

### 8.5 Plan round

```bash
python -m aai_harness.cli plan-round \
  --campaign-id campaign-demo \
  --objective "Optimize the candidate solution while preserving correctness and evidence requirements." \
  --child-id child-0001
```

`plan-round` automatically advances from `BASELINE_READY` to `ROUND_PLANNED` unless `--no-advance` is passed.

### 8.6 Prepare child

```bash
python -m aai_harness.cli prepare-child \
  --campaign-id campaign-demo \
  --child-id child-0001 \
  --parent-id baseline \
  --config-path <definition>/config.toml

python -m aai_harness.cli workflow-advance \
  --campaign-id campaign-demo \
  --action prepare_child \
  --child-id child-0001 \
  --artifact child_json=.aai/campaigns/campaign-demo/children/child-0001/child.json
```

### 8.7 Run executor backend

```bash
python -m aai_harness.cli run-codex-agent \
  --campaign-id campaign-demo \
  --child-id child-0001 \
  --objective "Optimize the candidate solution while preserving correctness and evidence requirements."

python -m aai_harness.cli workflow-advance \
  --campaign-id campaign-demo \
  --action run_agent \
  --artifact agent_run_json=.aai/campaigns/campaign-demo/children/child-0001/codex_agent_run.json
```

### 8.8 Evaluate

```bash
python -m aai_harness.cli run-child-eval \
  --campaign-id campaign-demo \
  --child-id child-0001 \
  --mode modal-full \
  --workers 10

python -m aai_harness.cli workflow-advance \
  --campaign-id campaign-demo \
  --action evaluate_child \
  --artifact child_eval_json=.aai/campaigns/campaign-demo/children/child-0001/child_eval.json \
  --artifact result_json=.aai/campaigns/campaign-demo/children/child-0001/result.json \
  --artifact diff_patch=.aai/campaigns/campaign-demo/children/child-0001/diff.patch
```

### 8.9 Gate and archive

```bash
python -m aai_harness.cli gate-archive \
  --evidence-json .aai/campaigns/campaign-demo/children/child-0001/result.json \
  --diff-patch .aai/campaigns/campaign-demo/children/child-0001/diff.patch \
  --kind variant

python -m aai_harness.cli workflow-advance \
  --campaign-id campaign-demo \
  --action gate_archive \
  --artifact gate_json=.aai/campaigns/campaign-demo/children/child-0001/gate.json \
  --artifact archive_manifest=<archive-manifest-path>
```

### 8.10 Summarize, update memory, admit population, select parent

```bash
python -m aai_harness.cli summarize-campaign --campaign-id campaign-demo
python -m aai_harness.cli workflow-advance \
  --campaign-id campaign-demo \
  --action summarize_campaign \
  --artifact campaign_summary_json=.aai/campaigns/campaign-demo/campaign_summary.json

python -m aai_harness.cli update-campaign-memory --campaign-id campaign-demo
python -m aai_harness.cli workflow-advance \
  --campaign-id campaign-demo \
  --action update_memory \
  --artifact memory_update_json=.aai/campaigns/campaign-demo/memory_update.json

python -m aai_harness.cli admit-population \
  --campaign-id campaign-demo \
  --child-id child-0001 \
  --definition <definition>

python -m aai_harness.cli population-status \
  --definition <definition>

python -m aai_harness.cli select-parent \
  --definition <definition>

python -m aai_harness.cli workflow-advance \
  --campaign-id campaign-demo \
  --action select_parent \
  --artifact selected_parent=.aai/archive/<definition>/selected-parent.json
```

## 10. Important invariants

Future agents must preserve these:

1. **AAI owns workflow transitions.** Do not let Codex, Claude Code, or any child executor advance global state implicitly.
2. **Child executors are bounded.** They should edit only `workspace/solution/` unless Mode 3 proposal review allows harness changes.
3. **Evaluator and scoring are protected.** Any changes to evaluator scripts must go through explicit harness proposal review.
4. **Evidence is required for promotion.** No variant promotion without `result.json`, `diff.patch`, `gate.json`, and archive manifest.
5. **Failures are data.** Failed or gated-out candidates should be archived as failed evidence where possible.
6. **Secrets are never persisted.** Store environment variable names, not key values.
7. **Runtime logs should be rich.** Failures should be diagnosable from runtime JSONL and stdout/stderr logs.
8. **Planner output is structured.** Text prompts can be derived from plan JSON, but plan JSON remains the authoritative decision artifact.
9. **Population memory should preserve lineage.** Every admitted member should record child id, campaign id, parent id, archive kind, gate status, metric, evidence path, and manifest path.
10. **Target packages are external.** Do not reintroduce historical retained-kernel directories unless explicitly requested.

## 12. Recommended next tasks for a future agent

### Task 1: Add workflow-aware runner

Add:

```text
aai_harness/workflow_runner.py
```

CLI:

```bash
python -m aai_harness.cli workflow-run --campaign-id ...
```

It should inspect `workflow.json`, execute only the current allowed next action, verify artifacts, and advance state.

### Task 2: Add `run-agent-round`

A higher-level command should run one complete AAI round:

```text
plan-round
prepare-child
run executor backend
run-child-eval
gate-archive
summarize-campaign
update-campaign-memory
admit-population
select-parent
```

It must still respect `workflow.py` transitions and should fail safely when state or required artifacts are inconsistent.

### Task 3: Upgrade parent selection

Replace simple latency-only parent selection with population-aware selection:

Inputs:

- best gated variants;
- failed candidates;
- traps;
- objective;
- novelty score;
- parent lineage;
- recent repeated failures.

Output:

```text
archive/<definition>/selected-parent.json
```

### Task 4: Add planner backends

Current planner is rule-based. Add backend abstraction:

```text
planner_backend = rule | codex | claude-code | loongflow-compatible
```

But all backends must write the same structured `PlannerDecision` schema.

### Task 5: Add tests

Minimum tests:

- dataclass JSON round-trip;
- workflow invalid transition rejects;
- workflow valid transition advances;
- `workflow-status` and `population-status` work with `slots=True` dataclasses;
- gate rejects incomplete evidence;
- Codex config never stores secret value;
- population admits failed and variant evidence but only gated variants become best members.

### Task 6: Strengthen artifact validation

`workflow-advance` should eventually verify:

- required artifacts exist;
- artifacts match expected type or schema;
- child id / parent id are consistent with plan;
- archive manifest references the same evidence record;
- evaluator result is not stale.

## 13. Known risks and caveats

### Deleted old examples

The branch removed historical kernel directories. README examples use `<definition>/config.toml`. A developer running commands must supply a real target package.

### Evaluator script assumptions

`child_eval.py` assumes existing evaluator scripts support the CLI flags used by the harness. This should be validated against real evaluator scripts and target packages before claiming full runtime readiness.

### `workflow-advance` is still lightweight

It enforces state/action validity, but does not yet validate artifact file existence or schema compatibility. This is a priority for robust autonomous use.

### Planner is not yet intelligent

`planner.py` currently emits a rule-based plan. This gives the correct control-plane artifact but not yet the full LoongFlow-style strategic reasoning.

### Population selection is not yet active in parent selection

`population.py` stores lineage, but `parent_selection.py` still needs to be integrated with it.

### PR is very large

The PR removes a large number of historical files. Reviewers should expect a very large deletion count because old full-agent traces and retained kernels were intentionally removed.

## 14. Coding style guidance

- Keep persistent artifacts JSON-first and timestamp-versioned.
- Prefer dataclasses with explicit schema fields for durable records.
- Use `write_json` / `read_json` helpers from `schemas.py`.
- Use `paths.py` for directory conventions.
- Do not store secrets.
- Use runtime logging for subprocess execution.
- Keep evaluator scripts as source of truth until a deliberate replacement is accepted.
- Add new CLI commands only when they map to a clear AAI workflow action or developer operation.
- Keep prompt text secondary to structured artifacts.

## 16. One-sentence project summary

AAI is a LoongFlow-style, workflow-controlled agentic optimization harness where Codex/CC/LoongFlow-compatible agents are bounded executor or planner backends, while AAI owns state transitions, evidence, gates, archives, summaries, memory, population checkpoints, and next-parent selection.
