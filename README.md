# Agentic AI Infrastructure Harness

This repository is now focused on the Agentic AI Infrastructure (AAI) harness layer.

AAI provides a LoongFlow-style control-plane architecture for bounded agentic optimization runs:

- own the hard workflow state machine instead of relying on prompt-only control;
- configure executor backends such as Codex by model name and API-key environment variable;
- start an AAI campaign from a target `config.toml`;
- create isolated child workspaces;
- let executor backends edit only bounded child candidate workspaces;
- evaluate, gate, and archive child evidence;
- summarize campaign state;
- update long-term memory through `harness-ledger.md` and `TRAPS.md`;
- maintain population/checkpoint lineage memory for future parent selection;
- mirror AAI artifacts into a full-agent-style trace tree for audit and handoff.

Legacy retained-kernel directories, old agent skills, historical reports, and the previous full-agent trace package were removed from this branch because the AAI harness does not need to vendor those artifacts. AAI now mirrors the useful full-agent trace schema using fresh AAI artifacts instead.

## Quick start

Run from `agent-assisted/`:

```bash
cd agent-assisted
export CODEX_API_KEY=<your OpenAI API key>

python -m aai_harness.cli configure-codex \
  --model gpt-5.5-codex \
  --api-key-env CODEX_API_KEY

python -m aai_harness.cli start \
  --config-path <definition>/config.toml \
  --campaign-id campaign-demo \
  --codex-model gpt-5.5-codex

python -m aai_harness.cli workflow-status \
  --campaign-id campaign-demo
```

AAI now uses `workflow.json` as the hard campaign control artifact. Codex is an executor backend, not the global workflow controller.

After a round, mirror AAI artifacts into full-agent-style trace layout:

```bash
python -m aai_harness.full_agent_trace_cli sync \
  --campaign-id campaign-demo \
  --definition <definition> \
  --iteration 1 \
  --child-id child-0001
```

`<definition>/config.toml` should point to a target package supplied by the user or generated by the AAI bootstrap workflow. The old retained-kernel examples are intentionally no longer vendored in this branch.

## Command meanings

- `configure-codex`: records Codex model, binary, sandbox, timeout, and API-key environment variable name in `.aai/codex_config.json`.
- `codex-status`: prints redacted Codex configuration and whether the API-key environment variable is present.
- `start`: resolves the target, creates `.aai/`, initializes a campaign, optionally configures Codex, and writes startup runtime logs plus `workflow.json`.
- `workflow-status`: prints current hard workflow state and allowed next actions.
- `workflow-advance`: records allowed workflow transitions.
- `plan-round`: writes a structured planner decision.
- `bootstrap`: packs and snapshots the current target solution as immutable baseline evidence.
- `prepare-child`: creates an isolated child workspace with `parent_solution/` and editable `workspace/solution/`.
- `run-codex-agent`: runs Codex CLI against the prepared child workspace and writes runtime logs.
- `run-child-eval`: runs pack/local/modal evaluator scripts against an existing child workspace without archiving.
- `run-child-round`: evaluates, gates, archives, and writes `round_report.json`.
- `summarize-campaign`: reads child round reports and writes `campaign_summary.json` / `campaign_summary.md`.
- `update-campaign-memory`: appends campaign findings into `harness-ledger.md` and repeated failures into `TRAPS.md`.
- `admit-population`: admits round evidence into population/checkpoint lineage memory.
- `full_agent_trace_cli sync`: mirrors AAI artifacts into the original full-agent-style trace tree.
- `select-parent`: selects the best archived parent for the next round.
